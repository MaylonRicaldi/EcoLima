# 07. Requisitos No Funcionales (RNF) - EcoLogística Lima

**Proyecto:** EcoLogística Lima - Optimizador de Rutas Sostenibles para DistriRápido S.A.C.
**Versión:** V_1_0_0
**Fecha:** 04 de septiembre de 2026
**Estándar Base:** ISO/IEC 25010 (SQuaRE) / arc42 - Escenarios de Calidad
**Principio:** Queda prohibido el uso de adjetivos calificativos sin umbral cuantitativo explícito. Toda medida es SMART.

---

## 1. Introducción

Los Requisitos No Funcionales definen los atributos de calidad del sistema mediante **Escenarios de Calidad** con estructura: **Fuente -> Estímulo -> Entorno -> Artefacto -> Respuesta -> Medida (SLA)**. Cada RNF se clasifica según ISO/IEC 25010 y se vincula a un instrumento de verificación y a condiciones locales de Lima Metropolitana (congestión extrema, cortes eléctricos en SJL, Ley N° 29733, conectividad 2G/3G).

## 2. Catálogo de Requisitos No Funcionales (Escenarios de Calidad)

### RNF-001 - Rendimiento / Eficiencia de Desempeño (ISO 25010: Performance Efficiency - Time Behaviour)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Rendimiento - Comportamiento Temporal / Utilización de Recursos |
| **Escenario de Calidad** | **Fuente:** Usuario Operador concurrente (hasta 15 usuarios operativos simultáneos). **Estímulo:** Solicitud de generación de rutas optimizadas para 150 pedidos / 15 vehículos. **Entorno:** Operación normal, carga pico horas punta 07:00-09:00 y 17:00-20:00, 80% capacidad del cluster. **Artefacto:** Módulo de Optimización (Metaheurística GA/Tabú/ACO) + API Backend. **Respuesta:** Procesar, validar restricciones (VRPTW + Green VRP) y retornar payload de rutas factibles. **Medida SLA:** Latencia **≤ 45 segundos** para caso base; **≤ 30 segundos** para re-optimización dinámica. **P95 ≤ 45s**, throughput ≥ 50 pedidos/min. |
| **Métrica SMART** | Tiempo de optimización P95 ≤ 45s (≤30s re-optimización). Cronómetro instrumentado desde POST /api/v1/rutas/optimizar hasta 200 OK. |
| **Condición Local** | Tráfico limeño varía abruptamente en horas punta; re-optimización rápida crítica para Av. Próceres / Panamericana Norte. |
| **Verificación** | Prueba de carga con k6 / JMeter: 150 pedidos sintéticos, 15 vehículos, dataset Lima Este real. Monitor: Prometheus + Grafana. Criterio éxito: 100% de ejecuciones bajo umbral en 50 iteraciones. |
| **Prioridad** | Alta |

### RNF-002 - Seguridad (ISO 25010: Security - Integrity, Authenticity)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Seguridad - Confidencialidad, Integridad, Autenticidad, No Repudio |
| **Escenario de Calidad** | **Fuente:** Atacante externo automatizado / interno malicioso. **Estímulo:** Intento de inyección SQL, XSS, CSRF o fuerza bruta en endpoint de autenticación (/api/auth/login). **Entorno:** Producción (Internet pública, TLS 1.3). **Artefacto:** API Gateway / WAF + Backend Auth + Base de Datos. **Respuesta:** Bloquear petición, sanitizar entrada parametrizada, registrar evento de auditoría (timestamp, IP, payload hash), notificar al rol Auditor y no exponer stacktrace. **Medida SLA:** **0%** de vulnerabilidades críticas/alta explotables OWASP Top 10 2021 verificadas en pentest; **100%** de endpoints con autenticación y autorización; bloqueo tras 3 intentos fallidos/15min; logs de seguridad retenidos ≥ 1 año. |
| **Métrica SMART** | OWASP ZAP / Burp Suite: 0 hallazgos críticos/altos. Cobertura SAST ≥ 90% pipelines. Tasa de bloqueo OWASP = 100%. |
| **Condición Local** | Cumplimiento obligatorio Ley N° 29733 - Protección de Datos Personales del Perú (datos de DNI, licencias, direcciones clientes). |
| **Verificación** | Análisis SAST (SonarQube), DAST (OWASP ZAP baseline), pentest anual, auditoría de logs. Revisión de políticas de contraseñas (≥12 chars, bcrypt cost 12). |
| **Prioridad** | Alta |

### RNF-003 - Fiabilidad / Disponibilidad (ISO 25010: Reliability - Availability)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Fiabilidad - Disponibilidad, Tolerancia a Fallos, Recuperabilidad |
| **Escenario de Calidad** | **Fuente:** Infraestructura cloud / red eléctrica local. **Estímulo:** Caída de un nodo en zona de disponibilidad primaria o corte eléctrico en SJL. **Entorno:** Operación 24/7, ventana operativa crítica 05:00-22:00. **Artefacto:** Cluster K8s / BD PostgreSQL con réplica + caché offline móvil. **Respuesta:** Failover automático hacia zona secundaria / réplica de lectura, reintento con backoff, cola de pedidos en modo offline-first en dispositivo móvil. **Medida SLA:** **SLA global ≥ 99.5%** en ventana operativa (05:00-22:00); **RTO ≤ 60 segundos**, **RPO ≤ 10 segundos**; tiempo fuera de servicio mensual ≤ 3.6 horas en horario operativo. |
| **Métrica SMART** | Uptime monitoreado con Blackbox + Heartbeat. RTO/RPO medidos en drill semestral de failover. |
| **Condición Local** | Cortes frecuentes de electricidad en SJL y conectividad inestable 2G/3G. Requiere respaldo local en móviles (IndexedDB + sync). |
| **Verificación** | Chaos engineering (chaos-mesh), pruebas de failover, healthchecks /health y /ready, SLO dashboard. |
| **Prioridad** | Alta |

### RNF-004 - Escalabilidad / Capacidad (ISO 25010: Performance Efficiency - Capacity)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Eficiencia de Desempeño - Capacidad / Escalabilidad Horizontal |
| **Escenario de Calidad** | **Fuente:** Crecimiento de demanda comercial. **Estímulo:** Incremento de carga de 250 a 1,000 pedidos diarios y de 15 a 50 vehículos. **Entorno:** Operación normal con autoscaling habilitado. **Artefacto:** Arquitectura de microservicios / API stateless + BD con pooling + cola de optimización. **Respuesta:** Escalar horizontalmente pods de optimización y workers sin degradar latencia. **Medida SLA:** Soportar **1,000 pedidos/día y 50 vehículos** con latencia P95 ≤ 45s (escalado). Degradación de latencia ≤ 10% al duplicar carga. Autoscaling trigger: CPU >70% o cola >20 jobs. |
| **Métrica SMART** | Prueba de estrés incremental 250→1000 pedidos. Métrica: throughput y latencia P95 con HPA (Kubernetes HPA min 3 / max 20 pods). |
| **Condición Local** | Expansión proyectada a Los Olivos, Comas, Independencia. Curva de demanda estacional (campañas). |
| **Verificación** | Load test k6 con ramp-up, monitoreo de HPA y métricas de consumo (CPU/mem). Test de particionamiento por distrito. |
| **Prioridad** | Media |

### RNF-005 - Usabilidad y Accesibilidad (ISO 25010: Usability / Accessibility - WCAG 2.1 AA)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Usabilidad - Operabilidad, Estética, Accesibilidad |
| **Escenario de Calidad** | **Fuente:** Conductor con educación primaria incompleta / discapacidad visual leve. **Estímulo:** Intento de consultar ruta asignada y completar entrega usando dispositivo móvil de gama baja. **Entorno:** Cabina de vehículo, luz solar directa, conexión 3G, pantalla 5". **Artefacto:** Frontend React (Modo Conductor). **Respuesta:** Presentar interfaz simplificada con iconos universales (sobre=entrega, camión=vehículo, semáforo=tráfico), tipografía ≥16px, contraste ≥4.5:1, flujo ≤3 taps hasta "Iniciar Ruta". **Medida SLA:** **WCAG 2.1 AA: 100%** criterios aplicables aprobados (Axe/Lighthouse ≥ 95 accesibilidad). **SUS ≥ 75** en test con 10 conductores. Tiempo de tarea "ver ruta + iniciar" **≤ 30 segundos** para usuario novato. Tasa de error de entrega por mala interpretación UI **≤ 5%**. |
| **Métrica SMART** | Auditoría Axe, Lighthouse, test moderado SUS, métrica de task completion. |
| **Condición Local** | Español peruano local (jerga opcional "vamos a la ruta"), iconografía universal por baja alfabetización digital. Versión simplificada obligatoria. |
| **Verificación** | Auditoría automática + evaluación heurística con experto + test de usabilidad con conductores reales. |
| **Prioridad** | Alta |

### RNF-008 - Sostenibilidad / Eficiencia Energética (Green Software - ISO 14083)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Eficiencia de Desempeño - Utilización de Recursos (ext. Green Software) |
| **Escenario de Calidad** | **Fuente:** Sistema en operación continua + stakeholder ambiental. **Estímulo:** Ejecución de consultas, transferencia de datos y cómputo de metaheurística. **Entorno:** Cloud con región de baja intensidad de carbono. **Artefacto:** Backend + BD + Frontend. **Respuesta:** Minimizar footprint computacional: consultas indexadas, paginación, compresión, cache Redis, imágenes optimizadas. **Medida SLA:** **Consultas SQL P95 ≤ 200 ms** (EXPLAIN ANALYZE), **transferencia por página ≤ 500 KB**, **consumo energético estimado ≤ 0.5 kWh / 1,000 optimizaciones** (estimado vía SCI - Software Carbon Intensity). **Huella de carbono del sistema** reportada trimestralmente según ISO 14083. |
| **Métrica SMART** | Query timing (pg_stat_statements), bundle size, SCI = (E * I) + M, donde E=energía, I=intensidad carbono. |
| **Condición Local** | Alineado con meta empresa carbono neutral a 3 años (3.5 ton CO₂/mes baseline). Selección de región cloud con energía renovable y compensación con 22 kg CO₂/árbol/año. |
| **Verificación** | Auditoría de queries, Lighthouse, Tag de carbono (Website Carbon Calculator), reporte trimestral SCI. |
| **Prioridad** | Media |

### RNF-009 - Precisión Funcional y Confiabilidad de Cálculo (ISO 25010: Functional Suitability - Correctness)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Adecuación Funcional - Corrección / Precisión |
| **Escenario de Calidad** | **Fuente:** Auditor externo / SUNAT contable. **Estímulo:** Cálculo de emisiones CO₂, costo TCO, ahorro económico y cumplimiento de ventanas de tiempo en dashboard y reportes. **Entorno:** Producción con datos operativos reales (diésel S/17.50/gal, mant. S/1.20/km, depreciación 20%). **Artefacto:** Motor de cálculo + Módulo de Reportes. **Respuesta:** Calcular con precisión determinística y trazable, con redondeo controlado. **Medida SLA:** **Precisión ≥ 99.9%** vs. cálculo manual auditado (muestra 100 rutas); **error de redondeo ≤ S/ 0.01** por transacción; consistencia entre dashboard y PDF **100%** (mismo motor). |
| **Métrica SMART** | Suite de tests de cálculo (pytest) con oráculo: 200 casos parametrizados. Diferencia absoluta ≤ umbral en pipeline. |
| **Condición Local** | Costos locales exactos: diésel, GNV S/12.50/m³, conversión S/5,000/veh. Reporte debe soportar auditoría NDC Perú. |
| **Verificación** | Tests unitarios de fórmulas (CO₂ = distancia * factor emisión), validación con auditor externo, checksum dashboard vs. PDF. |
| **Prioridad** | Alta |

### RNF-010 - Seguridad de Privacidad y Protección de Datos (ISO 25010: Security - Confidentiality + Legal Compliance)

| Campo | Descripción |
| :--- | :--- |
| **Categoría ISO 25010** | Seguridad - Confidencialidad / Cumplimiento Legal |
| **Escenario de Calidad** | **Fuente:** Titular de datos personales (conductor/cliente). **Estímulo:** Solicitud ARCO (acceso, rectificación, cancelación, oposición) o intento de acceso no autorizado a datos personales. **Entorno:** Producción, bajo Ley N° 29733 y su reglamento. **Artefacto:** BD + API + Logs. **Respuesta:** Cifrar datos en reposo (AES-256) y en tránsito (TLS 1.3), anonimizar logs, aplicar principio de mínimo privilegio, atender ARCO en ≤ 10 días hábiles, registro de consentimiento. **Medida SLA:** **100%** de datos personales cifrados en reposo/tránsito; **0** incidentes de exposición no autorizada; tiempo de respuesta ARCO **≤ 10 días hábiles**; auditoría anual de cumplimiento **100%** hallazgos críticos subsanados en ≤ 30 días. |
| **Métrica SMART** | Escáner de secretos, verificación TLS (testssl.sh A+), auditoría de cifrado at-rest (pgcrypto). Registro de solicitudes ARCO. |
| **Condición Local** | Ley N° 29733 exige registro ante APDP y consentimiento explícito. No almacenar historial médico sin consentimiento. |
| **Verificación** | Checklist Ley 29733, revisión de políticas de privacidad, pentest de autorización (IDOR), rotación de claves trimestral. |
| **Prioridad** | Alta |
