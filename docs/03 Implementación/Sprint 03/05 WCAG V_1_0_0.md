# Evaluación de Accesibilidad Web (WCAG)

**Nombre del Proyecto:** EcoLogística Lima – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.

**Nivel de Conformidad Objetivo:** WCAG 2.1 / 2.2 Nivel AA

**Herramientas Utilizadas:** Lighthouse / axe DevTools / WAVE

### Pruebas

#### Auditoría de accesibilidad con Lighthouse

![Prueba Lighthouse - Login](https://github.com/JericoOCH/EcoLima-Evidencias/blob/main/01-lighthouse-login.png?raw=true)

*Auditoría de Lighthouse sobre la pantalla de inicio de sesión (`http://localhost:5173/`). La categoría Accesibilidad obtuvo una puntuación de 100/100, y la herramienta lista 10 ítems adicionales para revisión manual, como el foco por teclado y el orden de tabulación.*

#### Resultados de axe DevTools

![Prueba axe DevTools - Resultados](https://github.com/JericoOCH/EcoLima-Evidencias/blob/main/02-axe-login-resultados.png?raw=true)

*Escaneo de axe DevTools (axe-core 4.13.0) con el estándar WCAG 2.1 AA sobre la vista `/dashboard`. El resultado fue de 0 incidencias en total: 0 problemas automáticos, 0 para revisión guiada y 0 manuales, sin problemas críticos, graves, moderados ni leves.*

#### Resultados de WAVE

![Prueba WAVE - Resultados](https://github.com/JericoOCH/EcoLima-Evidencias/blob/main/03-wave-resultados.png?raw=true)

*Resultados de WAVE sobre el módulo "Tráfico e incidentes". No se detectaron errores ni errores de contraste; se reportan 8 alertas (6 etiquetas de formulario huérfanas y 2 textos muy pequeños), 39 características de accesibilidad, 11 elementos estructurales y 60 elementos ARIA, con un AIM Score de 9.8 sobre 10.*

## 1. Resumen de Accesibilidad por Principios

- **Perceptible:** [ 95 % de Cumplimiento / Sin errores de contraste ni de texto alternativo en las tres herramientas, y el idioma de la página está declarado (`es`). WAVE reporta 2 alertas de texto muy pequeño y 6 etiquetas de formulario huérfanas que afectan la relación entre etiqueta y control. ]
- **Operable:** [ 100 % de Cumplimiento / Lighthouse y axe no reportan incidencias. Los elementos interactivos son alcanzables con la tecla Tab, lo cual se verificó manualmente. Los ítems de revisión manual de Lighthouse (foco, orden de tabulación y foco no atrapado) quedan como verificación complementaria. ]
- **Comprensible:** [ 98 % de Cumplimiento / Los textos son claros, la estructura de encabezados es coherente (`h1` y `h2`) y el idioma está identificado. Las etiquetas huérfanas reportadas por WAVE pueden dificultar la identificación de algunos campos de formulario. ]
- **Robusto:** [ 100 % de Cumplimiento / Sin incidencias de ARIA ni de HTML en axe DevTools y Lighthouse. WAVE detecta 60 elementos ARIA, como los `aria-label` de los módulos del menú lateral (Dashboard, Vehículos, Conductores, Clientes y Pedidos). ]

## 2. Hallazgos Principales y Correcciones

| Criterio de Conformidad | Problema Detectado | Componente Afectado | Solución Aplicada |
| :--- | :--- | :--- | :--- |
| **1.3.1 Información y relaciones** | 6 etiquetas de formulario huérfanas: hay elementos `label` que no están asociados a ningún control, por lo que un lector de pantalla no puede anunciar a qué campo pertenecen | Formularios del módulo "Tráfico e incidentes" | Se asoció cada `label` con su campo mediante los atributos `for` e `id`, o se envolvió el control dentro de la etiqueta |
| **1.4.4 Cambio de tamaño del texto** | 2 elementos con texto muy pequeño, que puede resultar difícil de leer, sobre todo con baja visión | Textos secundarios del módulo "Tráfico e incidentes" | Se aumentó el tamaño de fuente a un mínimo legible y se usaron unidades relativas (`rem`) para que el texto escale con el zoom |

## 4. Conclusión

La evaluación automática no detectó errores en las tres herramientas: Lighthouse obtuvo 100/100 en Accesibilidad, axe DevTools reportó 0 incidencias bajo WCAG 2.1 AA y WAVE reportó 0 errores y 0 errores de contraste, con un AIM Score de 9.8/10. Las únicas observaciones son las 8 alertas de WAVE, que se corrigieron según la tabla anterior. Dado que las herramientas automáticas solo detectan una parte de los problemas posibles, se recomienda complementar con pruebas manuales de teclado y lector de pantalla al incorporar nuevas pantallas.
